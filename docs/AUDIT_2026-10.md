# Invoice Them: Full Audit, October 2026

_Branch `claude/beautiful-cray-nl4sop`, starting from `84afce8` (the Confirm Email fix)._

The audit was triggered by the Confirm Email link going nowhere: a mismatch between code and dashboard settings that no test could catch.

**How it was done:**
- Three reviews read every file in the app:
  - auth, navigation and release configuration
  - database, security and storage
  - documents, money, PDF and reminders
- The live Supabase project (`noble-kite`) was checked for advisors, policies, function privileges, column types and logs.
- The most serious claims were checked against the source of the libraries the app uses.

**What this branch fixes:** the critical and high findings. The others are listed under "Still open".

## What was already solid

- **Data isolation:**
  - Row-level security is on for all 11 tables, with owner-only policies.
  - Every database function runs as the caller, with a fixed search path, and is off-limits to signed-out users.
  - The file bucket is private, with one folder per user.
- **App code:**
  - PDF text is HTML-escaped.
  - Payment links only allow `http(s)`.
  - Document-number reservation is atomic.
  - Money is stored as integer minor units.
- **Release configuration:**
  - All three EAS profiles carry the Supabase and RevenueCat keys.
  - The bundle ID and the `quoteapp` scheme match everywhere.
  - Restore Purchases, Privacy Policy and Apple's EULA are on the paywall.
  - The encryption export flag is set.
- **Live project:** no errors in the last 24 hours of logs.

## Fixed on this branch

### Auth and launch

| # | Problem | Fix |
| --- | --- | --- |
| 1 | Auth emails asked to return to `quoteapp:///auth/callback` (three slashes; that's what `Linking.createURL` builds in a release build). Supabase rejected it as not allowlisted and silently used the Site URL instead, which is the root cause of the original bug. Links only work today because the Site URL is now the app's callback. | One constant, `AUTH_CALLBACK_URL = 'quoteapp://auth/callback'`, with a unit test, used for sign-up, password reset and resend. |
| 2 | The app spun forever at launch if the profile failed to load (offline, or a brief Supabase error). Launch work also re-ran on every hourly token refresh. | A Try Again screen, and launch work is keyed on the user id. |
| 3 | Account deletion was only reachable after subscribing, which breaks App Store guideline 5.1.1(v). | A Delete Account link on the paywall. |
| 4 | After sign-out, the next account on the device saw the previous account's lists and filters, and got its overdue reminders. Sign-out also showed an error when offline, even though the device was signed out. | Every `SIGNED_OUT` clears all per-user stores, signed file URLs, scheduled reminders and the RevenueCat user. Sign-out never errors. |
| 5 | There was no way to resend a confirmation email. | Sign-in offers "Resend Email" when the email isn't confirmed. |
| 6 | The image picker plugin added generic camera and microphone permission prompts the app never uses. | Disabled in `app.json`. |

### Money and data loss

| # | Problem | Fix |
| --- | --- | --- |
| 7 | Autosave lost edits typed while a save was in flight. Failed saves were silent, and Done did nothing. | Saves run one at a time, and the editor only goes clean if nothing changed meanwhile. Errors show in the editor. |
| 8 | In comma-decimal locales (Europe, Latin America, Indonesia), "12,50" became 1,250.00. | Inputs accept `,` or `.` as the decimal point. Rounding works on the digits, not a float. |
| 9 | A document discount didn't lower tax, so clients were over-taxed. | The discount is spread across lines before tax. |
| 10 | Percent discounts over 100% gave negative totals, and the discount field couldn't take "7.5". | Discounts are capped at 100%, and the field keeps its own text while typing. |
| 11 | Money columns were 32-bit, so IDR or COP invoices above about 21.4M failed to save. | `bigint` (migration 005). |

### Server rules (migrations `005_audit_hardening.sql` and `006_audit_rules.sql`)

| # | Problem | Fix |
| --- | --- | --- |
| 12 | The server let non-draft documents be edited, payments go on drafts, estimates or void invoices, and zero or negative payments. Editing a payment un-voided an invoice. | The server enforces the same rules the app follows. |
| 13 | A user could attach line items, signatures, payments or recurring schedules to another user's document. A planted schedule made the nightly job create invoices in the victim's account. | A composite foreign key ties each child row to its document's owner. |
| 14 | One failing recurring schedule rolled back the nightly run for every user. | Each schedule runs in its own subtransaction. |
| 15 | Identical prefixes, or toggling the yearly reset, handed out numbers that were already taken. | Taken numbers are skipped, and Settings rejects identical prefixes. |
| 16 | Delete All Data left the payment link in place. | The payment link is cleared. |

### Storage, deletion and backup

| # | Problem | Fix |
| --- | --- | --- |
| 17 | Account deletion and Delete All Data only removed the first 100 files per folder, missed nested folders and ignored errors. A failure part-way left an account that could still sign in with no data. | A paged, recursive folder walk. Account deletion removes files first, then the user, and the existing cascades remove every row. |
| 18 | The backup silently stopped at 1,000 rows per table, and left the client data in the cache. | The backup pages through every table, and the file is deleted after sharing. |
| 19 | PDFs were stored under the document number, so prefixes like `INV/` or `#` broke Share and Email. | PDFs are stored under the document id. |
| 20 | Deleting a document removed its files before the row. | The row goes first. |

### Wrong numbers and silent failures

| # | Problem | Fix |
| --- | --- | --- |
| 21 | Document actions (Issue, Cancel, Convert, Share) failed silently, and a missing document spun forever. | An alert on failure, and a "no longer exists" screen with Try Again. |
| 22 | Overdue reminders re-fired for every overdue invoice on each launch. | Only future reminders are scheduled. |
| 23 | Home's money tiles counted issued estimates as money owed, and counted converted estimates twice. | Invoices only. |
| 24 | The paid-by-period chart put payments a day early for users west of UTC. | Dates are compared as calendar strings. |

## Still open (medium and low)

- **Dates use UTC instead of local time.**
  - New-document issue date, default due date and "overdue" (`documents.repo.ts:220,287-291`, `statusMachine.ts:25`).
  - The server's `current_date` and the yearly reset.
  - Effect: off by a day for part of each day outside UTC.
- **RevenueCat.**
  - A failed check fails closed and never retries until relaunch (`useSubscriptionStore.ts:55-82`).
  - The paywall promises a free trial without checking eligibility.
  - It spins forever if there is no current offering.
  - A purchase that grants no entitlement is silent.
- **Auth hardening.** Move to the PKCE flow so a crafted `quoteapp://auth/callback#access_token=…` link can't sign the device into someone else's account, and route resets on `PASSWORD_RECOVERY`. This needs testing on a phone.
- **No https fallback for email links** opened on a desktop or in an in-app mail browser. Possible fixes: a `site/auth/callback.html` bounce page, or universal links.
- **Multiple currencies.** Report totals add different currencies together. Catalog prices are in the default currency and are copied unconverted.
- **Client picker** inherits the Clients tab's search and "balance only" filter.
- **Issued PDFs read live client details,** so editing or deleting a client changes old invoices. The fix is to snapshot the client when issuing.
- **The default tax rate is never applied** to new taxable lines.
- **Recurring.** Editing a schedule resets `runs_count` and re-anchors it (31st → 28th). A past start date backfills up to 12 drafts without warning.
- **Lists and reports stop at 1,000 rows** (documents, clients' balance filter, reports).
- **Performance** (Supabase advisor):
  - Wrap `auth.uid()` as `(select auth.uid())` in policies.
  - Add owner and foreign-key indexes on `line_items`, `signatures`, `settlements`, `activity_logs` and the `converted_*` columns.
- **Low:**
  - `quantity` is `real` (float4).
  - Signed URLs are cached for the whole session.
  - "Shared" or "emailed" is logged even when cancelled.
  - There's no un-archive screen.
  - `BusinessProfile.id` is typed `1`.
  - Stale README and `PROJECT_STATUS.md` claims (paywall not built, camera permission removed, four-step onboarding).

## Rolling out

1. **Migration 005** (bigint money and same-owner foreign keys) was applied to `noble-kite` on 2026-10-20 as `audit_hardening_columns_and_owner_fks`.
2. **`delete-account`** was redeployed on 2026-10-20 as version 3. The live app calls it the same way.
3. **Migration 006 (server rules) still needs applying.** The Supabase connector timed out on every migration that defines functions, so it hasn't been run.
   - **How:** paste `supabase/migrations/006_audit_rules.sql` into Supabase → SQL Editor and run it. It's a single transaction, so it either applies fully or not at all.
   - **Compatibility:** it works with the build already on the App Store.
   - **Until it's applied:** the server doesn't yet enforce the edit and payment rules, a failing recurring schedule still stops the nightly run, and taken numbers aren't skipped. Nothing breaks in the meantime.
4. **Phone test before `eas build`:**
   - Sign up and tap the email link.
   - Request a password reset.
   - Type `12,50` with the phone's region set to Germany.
   - Edit a draft on a slow network and tap Done.
   - From the paywall, delete a throwaway account.
5. **Ship.** `npx eas-cli@latest build --profile production --platform ios`, then `npx eas-cli@latest submit --platform ios`.
